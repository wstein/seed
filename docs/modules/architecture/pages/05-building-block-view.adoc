= Building Block View
:page-layout: default

Describe the major subsystems, modules, or services.

== Top-Level Structure

Seed is a single Elixir library application (`:seed`) whose modules form
the runtime. The building blocks below mirror the build order in
xref:04-solution-strategy.adoc[Solution Strategy].

=== Implemented

* `Seed` — top-level facade and project entry point; `Seed.parse/4` and
  `Seed.tokenize/2` run the lex-to-parse pipeline from loaded grammars and
  a binary input, returning `{:ok, _} | {:error, [diagnostic]}`.
* `Seed.Token` — the token value (type, text, source positions, channel)
  and the well-known token-type constants (`EOF`, invalid type).
* `Seed.Vocabulary` — the mapping from integer token types to literal,
  symbolic, and display names, used for diagnostics and tree rendering.
* `Seed.CharStream` — an immutable character input stream over a UTF-8
  binary, offering lookahead, consume, mark/seek, and text extraction.
* `Seed.TokenStream` — an in-memory buffer of tokens with positional
  lookahead, the bridge between a lexer's output and a parser's input.
* `Seed.IntervalSet` — merged inclusive integer intervals, the symbols a
  set or not-set transition matches.
* `Seed.ATN`, `Seed.ATN.State`, `Seed.ATN.Transition`,
  `Seed.ATN.LexerAction` — the ATN graph as an immutable value: states and
  transitions are single structs discriminated by an atom, and edges
  reference other states by integer number.
* `Seed.ATNDeserializer` — reconstructs the ATN from the tool's serialized
  integer stream, validated against the canonical runtime
  (xref:09-architecture-decisions.adoc#adr-002[ADR-002]).
* `Seed.ATN.PredictionContext`, `Seed.ATN.ATNConfig`,
  `Seed.ATN.ATNConfigSet`, `Seed.ATN.LexerActionExecutor` — the
  configuration and call-stack types the simulators reason over.
* `Seed.LexerATNSimulator` — matches one token by simulating the lexer
  ATN (closure, reach, longest-match rollback). A lexer semantic predicate
  `{...}?` gates its transition through the lexer's `sempred` callback; a
  custom evaluator bypasses the DFA cache, since its result may vary with
  position.
* `Seed.Lexer` — the token-producing driver: lexer commands, modes, and
  emission. Validated against the reference lexer's token streams.

* `Seed.ATN.PredictionContext` (array form + merge), `Seed.ATN.SemanticContext`,
  `Seed.ATN.ParserATNConfigSet` (context-merging), and `Seed.ATN.PredictionMode`
  — the parser prediction data layer.
* `Seed.ParserATNSimulator` — adaptive LL(*) prediction, two-stage SLL-first
  with full-context fallback. SLL builds the start state with an empty outer
  context (shared across call sites); a config that dips into the outer context
  is carried at its rule-stop, so a clean exit stays unique while a
  context-sensitive decision conflicts and retries in full context (where the
  start state is built from the real call stack). The left-recursion precedence
  filter applies to the full-context pass. When no alternative can consume the
  next token, prediction selects an alternative that has reached the decision's
  rule-stop state. When conflicting alternatives carry semantic predicates
  (`{...}?`), they are evaluated through the parser's `sempred` callback to pick
  the alternative whose predicate holds.
* `Seed.Parser` and `Seed.ParserInterpreter` — the ATN-walking tree builder,
  including left-recursion (from a sub-rule or directly as the start rule).
  Validated against the reference parser's trees.
* `Seed.DFACache` and `Seed.Application` — a supervised, bounded ETS table
  memoizing the lexer's and parser's ATN decisions
  (xref:09-architecture-decisions.adoc#adr-005[ADR-005]); a pure speedup.
* `Seed.Grammar` and `Seed.Interp` — a grammar's runtime metadata (ATN,
  vocabulary, rule/channel/mode names) loaded from an ANTLR `.interp` file,
  so a grammar can be parsed at run time with no code generation.
* `Seed.Diagnostic` — a structured lex/parse problem (code, severity,
  position, message). The lexer returns `{:ok, tokens} | {:error,
  [diagnostic]}`; the parser returns `{:ok, tree} | {:error, diagnostics,
  tree}` — it always recovers, so the partial tree is returned alongside the
  diagnostics, with `Seed.ErrorNode` leaves (including a fabricated `<missing
  …>` token for an insertion) marking the recovery points, as ANTLR's
  `ErrorNode` does. The parser recovers from errors at two levels,
  accumulating one diagnostic each:
+
--
** *Single-token* — *deletion* of an extraneous token and *insertion* of a
   missing one. Insertion is gated by an ATN reachability check
   (`expects?/3`): a missing token is only fabricated when the real current
   token can still continue the rule past it, which keeps recovery from
   looping.
** *Panic-mode resync* (`Seed.Parser.sync/1`) — when no single-token
   recovery applies — either a token mismatch or a no-viable-alternative at a
   decision — the parser discards input up to the current rule's follow set
   (the resynchronization set, computed from the active frames with
   `expects?/3`) and unwinds to that rule's stop state. Every recovery either
   consumes a token or pops a rule, so it always makes progress.
--

* `Seed.Generated` — the Elixir code-generation target. `use Seed.Generated,
  parser: …, lexer: …` reads the ANTLR `.interp` artifacts at compile time,
  bakes the deserialized grammars into the module (registered as
  `@external_resource`), and emits named entry points — `parse/1`, `parse/2`
  (by rule name or index), and a `parse_<rule>/1` per rule — that delegate to
  the runtime. No grammar work happens at run time.
* `Seed.ParseTreeWalker` / `Seed.ParseTreeListener` and
  `Seed.ParseTreeVisitor` — traversal of the produced tree. The walker drives
  a listener through a depth-first walk, threading an accumulator
  (`enter_rule`/`exit_rule` around children, `visit_terminal`/
  `visit_error_node` at leaves); the visitor dispatches per node and computes
  a value, descending with `visit_children`. Both are behaviours whose `use`
  macro supplies base defaults, so an implementation overrides only what it
  needs — the functional analogue of ANTLR's listener/visitor and their base
  classes. (ANTLR's *error listeners* have no counterpart: Seed reports
  problems as `Seed.Diagnostic` values, per
  xref:09-architecture-decisions.adoc#adr-003[ADR-003].)
* `Seed.XPath` — locates tree nodes with an XPath-like query (`/`, `//`,
  rule/token/literal names, `*`, `!`), resolved against the grammar.
* `Seed.TokenStreamRewriter` — immutable insert/replace/delete edits over
  token positions, rendered back to text with `text/1`.
* `Seed.TreePatternMatcher` — compiles a tree pattern (`<ID> = <expr>;`) and
  matches it against a parse tree, binding tags to nodes (`Seed.TreePattern`,
  `Seed.ParseTreeMatch`). Rule tags are made matchable by `Seed.ATN.BypassAlts`,
  which adds the reference's bypass-alternatives to a parser ATN.

=== Planned

Remaining runtime gaps and their sequencing are tracked in the
xref:manual:feature-parity.adoc[feature-parity roadmap] (notably the Elixir
codegen target and the self-hosting `.g4` tool). The SLL-first prediction
optimization, formerly listed here, has landed in `Seed.ParserATNSimulator`.
