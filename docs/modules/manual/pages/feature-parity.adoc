= Feature Parity And Roadmap
:page-layout: default

Where Seed stands against the reference runtimes, and the plan to close the
remaining gaps.

== Short Answer

*Parity is not yet reached.* Seed is a faithful, production-quality *runtime*
for a large and useful subset of the ANTLR feature set, but several runtime
features are still missing, and two of the gaps are *architectural*: as an
ATN *interpreter*, Seed cannot execute the host-language code that embedded
actions (`{...}`) and custom semantic predicates (`{...}?`) compile to.

== What "Parity" Means Here

Seed is a runtime, not a tool. It begins at the serialized grammar artifact
and ends at the parse tree
(xref:architecture:03-context-and-scope.adoc[Context And Scope]); grammar
analysis, ATN construction, and `.g4` parsing stay with the ANTLR/antlr-ng
*tool*. Parity is therefore measured against the reference *runtimes*.

A useful simplification follows from
xref:architecture:09-architecture-decisions.adoc#adr-002[ADR-002]: the
serialized ATN is **version 4** across ANTLR4, antlr-ng, and ANTLR5, and the
prediction algorithm is unchanged between them. At the runtime contract Seed
targets, the three references are effectively one. They differ in host
language (Java / TypeScript / Kotlin) and in tool features, not in the
runtime semantics Seed must match — so the matrix below uses a single
*ANTLR reference runtime* column and calls out the rare divergence in notes.

[]
Legend: ✅ at parity · ◐ partial · ✗ missing (in scope) · ⊘ out of scope or
N/A by design.

== Feature Matrix

=== Grammar artifact and compatibility

[cols="3,2,5",options="header"]
|===
| Feature | Seed | Notes

| Serialized ATN v4 deserialization | ✅ | `Seed.ATNDeserializer`; the shared contract of ANTLR4/antlr-ng/ANTLR5.
| `.interp` runtime loading | ✅ | `Seed.Interp` → `Seed.Grammar`. Seed-specific convenience; reference runtimes embed the ATN in generated source instead.
| `.g4` parsing, grammar analysis, ATN construction | ✗ (planned) | Currently produced by the ANTLR/antlr-ng tool. A self-hosting Elixir tool is planned as a separate milestone (xref:architecture:09-architecture-decisions.adoc#adr-007[ADR-007]).
|===

=== Lexer

[cols="3,2,5",options="header"]
|===
| Feature | Seed | Notes

| ATN simulation, longest match, rule-order tie-break | ✅ | `Seed.LexerATNSimulator`, validated against the reference token streams. Unicode code points and string escapes are diffed against the reference on the `Misc` grammar.
| Modes (`mode` / `pushMode` / `popMode`) | ✅ | Mode stack in `Seed.Lexer`; diffed against the reference's generated parser on the `Modes` grammar.
| Channels (tagging tokens) | ✅ | `channel(...)` sets the token channel; the hidden channel (`Modes`) and a custom named channel (`Misc`) are diffed against the reference, both correctly filtered from the parser.
| Commands: `skip`, `more`, `type`, `channel`, `mode`, `pushMode`, `popMode` | ✅ | `Seed.ATN.LexerActionExecutor`. A token built across rules with `more` and finalized with `type()` is diffed against the reference on the `More` grammar.
| Custom embedded actions (`{...}`) | ✗ | Needs host code; currently a no-op.
| Lexer semantic predicates (`{...}?`) | ✅ | Evaluated during the rule's closure via a caller-supplied evaluator (`Seed.Lexer.new/3`, or `Seed.tokenize/3`'s `:sempred`); the default treats every predicate as satisfied. A custom evaluator bypasses the lexer DFA cache (its result may vary with position), as the reference cannot fold a predicate into a DFA edge.
|===

=== Token streams

[cols="3,2,5",options="header"]
|===
| Feature | Seed | Notes

| Buffered stream, relative lookahead, seek | ✅ | `Seed.TokenStream`.
| Off-channel filtering for the parser (`CommonTokenStream`) | ✅ | `Seed.TokenStream`'s `lt`/`la`/`consume` skip tokens routed to a non-default channel (e.g. `channel(HIDDEN)`); they stay in the buffer, addressable by absolute position with `get/2`.
| `TokenStreamRewriter` | ✅ | `Seed.TokenStreamRewriter` — immutable insert/replace/delete over token positions, rendered with `text/1`. Operates over the full buffer (off-channel tokens included).
|===

=== Parser and prediction

[cols="3,2,5",options="header"]
|===
| Feature | Seed | Notes

| Adaptive LL(*) prediction | ✅ | `Seed.ParserATNSimulator`, full rule-invocation context (xref:architecture:09-architecture-decisions.adoc#adr-002[ADR-002]).
| Left recursion / precedence climbing | ✅ | As a sub-rule and directly as the start rule; left- *and* right-associative (`<assoc=right>`) operators diffed against the reference on the `Calc` grammar.
| Precedence predicates | ✅ | The precedence filter evaluates them.
| Custom semantic predicates (`{...}?`) | ✅ | Evaluated during conflict resolution via a caller-supplied `:sempred` callback (`Seed.ParserInterpreter.parse/4`, or an overridable `sempred/3` in `Seed.Generated`); the default treats every predicate as satisfied. The interpreter still cannot run the host code itself — the caller supplies the decision.
| Embedded actions (`{...}`) | ✗ | No-op on the matched path. Plain actions need a typed-context/attribute model to be meaningful and are folded into the codegen target (Roadmap C); post-parse computation is already served by the tree walk.
| SLL fast path with LL fallback | ✗ | Seed always predicts in full context — correct, but slower and less cacheable across call sites (see Roadmap D).
| Decision memoization | ◐ | `Seed.DFACache` (ETS) memoizes start states and edges; it is a pure speedup, not the reference's persisted DFA edge structure.
|===

=== Parse tree

[cols="3,2,5",options="header"]
|===
| Feature | Seed | Notes

| Rule-context tree, terminals, error nodes | ✅ | `Seed.ParserRuleContext`, `Seed.TerminalNode`, `Seed.ErrorNode`.
| `toStringTree` | ✅ | `Seed.Trees`, validated against reference output.
| Listener + walker | ✅ | `Seed.ParseTreeListener`, `Seed.ParseTreeWalker`.
| Visitor | ✅ | `Seed.ParseTreeVisitor`.
| Typed per-rule contexts, labeled alternatives, typed accessors | ✗ | Contexts are generic, keyed by `rule_index` (see Roadmap C).
| XPath over trees | ✅ | `Seed.XPath.find/3` — `/`, `//`, rule/token/literal names, `*`, and `!` inversion, resolved against the grammar.
| Tree pattern matching | ✗ | Not implemented (see Roadmap E).
|===

=== Errors and recovery

[cols="3,2,5",options="header"]
|===
| Feature | Seed | Notes

| Structured diagnostics | ✅ | `Seed.Diagnostic` returned as values (xref:architecture:09-architecture-decisions.adoc#adr-003[ADR-003]).
| Single-token deletion and insertion | ✅ | Insertion gated by an ATN reachability check so it cannot loop.
| Panic-mode resynchronization (follow sets) | ✅ | For both a token mismatch and a no-viable-alternative decision.
| Error nodes in the recovered tree | ✅ | Including a fabricated `<missing …>` token for an insertion.
| Error strategy: recover (default) or bail | ✅ | `Seed.ParserInterpreter.parse/4`'s `:bail` option aborts at the first error with one diagnostic and no tree, the `BailErrorStrategy` equivalent; the default recovers. A fully pluggable strategy object is not provided.
| Error listeners | ⊘ | By design — structured diagnostics-as-values serve the same tooling purpose (ADR-003).
|===

=== Code generation and host runtime

[cols="3,2,5",options="header"]
|===
| Feature | Seed | Notes

| Compile-time target module (`use Seed.Generated`) | ◐ | Bakes the grammar and emits named entry points, but is interpreter-backed — it does not generate per-rule methods or typed contexts (see Roadmap C).
| Pure-functional, immutable, BEAM-native runtime | ✅ | A property the reference runtimes do not have (xref:architecture:09-architecture-decisions.adoc#adr-004[ADR-004]); Seed's distinctive strength.
| Multi-target tool | ⊘ | N/A — Seed is one target's runtime, not the tool.
|===

== Implementation Plan

Ordered by correctness impact first, then value. Each phase is independently
shippable behind the project's quality gate (`make verify`).

[cols="1,4,3",options="header"]
|===
| Phase | Work | Closes

| A. Off-channel token stream _(done)_
| `Seed.TokenStream` filters non-default-channel tokens from `lt`/`la`/
  `consume` (a `CommonTokenStream` equivalent), keeping them addressable for
  tooling.
| Correctness for grammars that route whitespace/comments to a hidden
  channel rather than `skip`.

| B. Predicate callbacks _(done)_
| The caller (and `Seed.Generated`) supplies a predicate evaluator keyed by
  rule and predicate index; the parser evaluates it during conflict
  resolution and the lexer during a rule's closure. Embedded actions are
  deliberately excluded — without typed contexts they have no attributes to
  act on, so meaningful action support is folded into Phase C, and post-parse
  work is already covered by the tree walk.
| Custom semantic predicates — the largest semantic gap — without abandoning
  the interpreter model.

| C. Full Elixir codegen target
| Extend `Seed.Generated` to emit typed per-rule context structs, labeled-
  alternative accessors, and listener/visitor scaffolding, optionally inlining
  predicates/actions as generated functions (subsumes B for generated code).
  Performance codegen follows the specialization ladder in
  xref:architecture:09-architecture-decisions.adoc#adr-008[ADR-008] — flatten
  the interpreter first, then emit inspectable Elixir AST, benchmark-gated.
| Typed contexts and an ergonomic, ANTLR-target-like generated API.

| D. SLL-first prediction
| Add a context-free SLL pass with full-context fallback on conflict, with a
  DFA cacheable across call sites. Needs a faithful port of the reference's
  full-context closure semantics (a first attempt was reverted for
  mispredicting the context-sensitive `ctx_b` case), and is governed by the
  benchmark gate in xref:architecture:09-architecture-decisions.adoc#adr-008[ADR-008].
| The main remaining prediction-time performance lever (correctness is already
  validated under full context).

| E. Tooling parity
| `TokenStreamRewriter`, tree XPath, tree pattern matching, and a bail error
  strategy (`Seed.ParserInterpreter.parse/4`'s `:bail` — done).
| Convenience APIs that round out runtime parity.
|===

After A–C, Seed reaches functional parity for grammars that use embedded
actions and predicates; D and E are performance and convenience.

Separately, the *self-hosting tool* (`.g4` → ATN, planned in
xref:architecture:09-architecture-decisions.adoc#adr-007[ADR-007]) is its own
track: it removes the external Java/antlr-ng build dependency but does not
change what a grammar can do at run time. The two tracks are independent —
the runtime gaps above are about *capability*, the tool is about
*self-hosting*.
